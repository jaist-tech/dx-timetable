# 経路検索（route.html / planner.js）の仕様と連携

## 要約

のみバスを含む全路線から任意の 2 停留所間の経路を探す新ページ `route.html` と，画面に依存しない探索部 `public/js/planner.js` を追加した．既存の検索・詳細・マップの画面と探索は変えていない．入口は `about.html` のカード 1 つ．マップアプリは URL 引数か `Planner.plan()` で使える．

| 項目 | 状態 |
|---|---|
| 探索 | RAPTOR（乗車回数ごとの最早到着）を出発時刻ごとに繰り返す．5 条件（早：到着時刻順・楽：乗換回数順・安：安い順・待ち時間順・乗車時間順．値は time・transfers・fare・wait・ride）の並べ替え，乗換上限（0〜5・無制限），徒歩の乗換，出発／到着指定 |
| 試験 | `node --test tests/planner.test.js`（12 件）．全探索との突合 150 組一致．既存 6 経路の旧探索の結果は，新探索で全件説明できる（7 組） |
| 速度（Node） | 探索 1 回 約 6〜10 ms（スマホ実機は未計測） |
| 金額の条件 | `data/fares.json`（`docs/fares.md`．大人・現金・片道）を読んで有効．のみバス同士の乗継は 2 本目を無料として計算．区間の運賃が未登録（空港バスの途中停留所どうし等）の経路は金額なし |
| 地図の線 | 2026-10-09 点検．`route.html` の地図は停留所を直線で結んでいたため，道・線路に沿う形（`data/route/shapes.json`）に改めた．結果は下の「地図の線の点検」 |
| 徒歩の乗換 | 座標のある停留所の組（直線 1300 m 以内 893 組）は OSM の歩行者の道のり（`data/route/walk.json`）÷歩く速さ．道に結べなかった 1 停留所（上和気）は直線距離の近似．`routes.json` の個別の値（JAIST↔先端大学ほか）は優先．結果の徒歩の行に根拠（道のり・概算・個別）を表示．乗換の時間は一律ではなく停留所の組ごとの道のりから出す．座標が無い停留所は対象外 |

あなたの作業: `route.html` を開いて使い勝手を確かめる（閲覧サーバーの URL は完了の付箋）．

## 2 マップアプリからの使い方

### A URL 引数

```
route.html?from=JAIST&to=金沢駅&date=2026-10-10&arrive=18:30&prio=time&auto=1
```

`from`・`to` は停留所名か `緯度,経度`（座標は徒歩 15 分以内の近い 5 停留所を候補にする）．`depart=HH:MM` または `arrive=HH:MM`，`prio=time|transfers|wait|ride|fare`．

画面に時刻の入力欄は無く，選んだ日の全出発（`depart: '00:00'`・`window: 2000`・`results: 1000`）を表示順で一覧にする．今日は今の時刻より前の出発を薄くして最初の候補へ移る．`depart=` はその時刻を今の時刻の代わりに使い，`arrive=` は最初の 1 回だけ到着指定で探す（従来どおり上位 5 件）．2026-10-09 の測定（Node．1 日分の探索）: JAIST→金沢駅 22 件 77 ms，JAIST→小松空港（乗換無制限・待ち時間順）11 件 64 ms，金沢駅→加賀温泉駅（乗換無制限・乗車時間順）31 件 80 ms．

### B JS の部品

```js
const net = await Planner.load('https://<配信元>/data/');   // 時刻表・座標・運賃を取得（CORS 可の配信元）
await net.ensureDate('2026-10-10');
const res = Planner.plan(net, {
  date: '2026-10-10', from: {lat: 36.44, lon: 136.59}, to: '金沢駅',
  arrive: '18:30', priority: 'time', maxTransfers: 3,
  walk: {enabled: true, maxMeters: 400, speed: 80},   // maxMin（分）も受け，距離 = 分 × 速さ
});
```

結果は `{apiVersion: 1, date, count, journeys: [{dep, arr, depStr, arrStr, total, transfers, wait, ride, walk, fare, legs: [...]}]}`．分は 0 時からの整数（24 時超あり）．`legs` の要素は `{type:'trip', routeId, routeName, from, to, dep, arr, stops:[{name,time}]}` または `{type:'walk', from, to, minutes, dep, arr}`．形を変えるときは `apiVersion` を上げる．

## 3 探索の決め方（既存との違い）

- 出発指定は，出発地で乗れる便の出発時刻ごとに探索して候補を集め，出発が遅く・到着が早く・乗換が少ないものに劣る候補を除く（既存の「最も遅い便を選ぶ逆向き探索」とは違い，全候補から並べ替える）．
- 並べ替えは辞書式（選んだ条件→到着時刻→合計時間→乗換回数→金額→出発が遅い順）．「早：到着時刻順」は出発指定のとき到着が早い順，到着指定のとき出発が遅い順（同じなら到着が早い順）．
- 乗換が 1 回増えて 3 分以上縮まない候補は，既定では除く（詳細設定で解除）．
- 乗換の最小時間は `routes.json` の `transfers`（既定 5 分）．徒歩の乗換は徒歩の分＋余裕 2 分．歩く距離の上限（検索ページでは設定せず 400 m に固定．駅構内などを考慮できないため．planner の `maxMeters` は残す）は道のり（概算は直線×1.3）で判定し，歩く速さは所要の分だけに使う．徒歩は 1 回の乗換につき 1 区間（連続する徒歩はつながない）．
- 停車する停留所の組が違う便（通過便）は別の系統として扱う（最早の便が目的地に止まらない場合の誤りを防ぐ）．
- のみバスの「(折り返し)」は同じ停留所に名寄せ．他路線との名寄せは名前の完全一致（能美根上駅・鶴来駅・岩本・灯台笹・小松駅．野々市駅は別の駅のため路線別の別名で分ける）．JAIST↔先端大学（徒歩 3 分）と西金沢↔新西金沢は `routes.json` の徒歩の乗換．

## 4 既知の制約（未対応）

- のみバス 137 停留所の座標が未確認（OSM と名前が一意に一致した分だけ採用）．座標が無い停留所は，徒歩の乗換と座標指定の出発地の候補に入らない．
- 「先端大学前」と JAIST の関係，「岩本」「灯台笹」の同一性は OSM の座標で確認済み（下の「乗換の時間と停留所の調査」）．
- 徒歩の道のりは OSM の道に停留所を最寄りの道の点（60 m 以内）で結んで求める．OSM の道の抜け・通行できない道（私道・フェンス等）・勾配や信号の待ちは反映しない．道のり 1500 m 超・直線 1300 m 超の組は表に無く歩かない．
- 同じ名前の停留所・駅の中の乗換（`routes.json` の `transfers`）は，鶴来駅 2 分・小松駅 3 分のほかは既定の 5 分（OSM で乗り場は 20〜170 m 以内と確認し，余裕を見て変えない．下の調査）．野々市駅は IR いしかわ鉄道と北陸鉄道（石川線）が約 2.3 km 離れた別の駅であるため，北鉄側を「野々市駅（北鉄）」の別の地点に分けた（2026-10-09．`routes.json` の `place_aliases`．両者の間に乗換・徒歩の結びは無い）．
- 金額は大人の現金・片道（IC・学割・定期は含まない）．金額を重視する並べ替えは候補の中から選ぶ．
- 待ちの上限（既定 120 分）は，各停留所の最早到着だけを残す探索と組み合わさるため，「最早の到着では接続便まで上限を超えるが，後の到着なら収まる」経路は返さないことがある（上限を「無制限」にすると返る）．
- 待ち時間・乗車時間・金額を重視する並べ替えは，出発時刻ごとの最早到着の候補の中から選ぶ（それらの最小値を直接は探索しない）．
- 終発後の翌日の便は探索しない（既存と同じ）．ただし 0 件のときは原因を調べて画面に出す（下の「0 件の原因」）．

## 0 件の原因（2026-10-09）

並べ替え（早・楽・安・待ち・乗車）は候補を落とさない．0 件になるのは候補が無いときだけで，`plan()` は `reason` を返す．

| reason | 意味 | 画面 |
|---|---|---|
| `window` | 指定の時刻から 3 時間以内に便が無い（例: 0〜3 時台の出発） | 幅を広げた結果を表示し，「最も近い便は HH:MM」を添える（`widened: true`） |
| `limit` | 乗換・待ちの上限を外すと経路がある | 「乗換 n 回以上にすると経路があります」 |
| `after-last` | その日の終発より後 | 「HH:MM 発が最終」＋翌日の始発（日付の選択肢に翌日があるとき） |
| `before-first` | 到着指定で，その日の最も早い到着より前 | 「HH:MM 着が最も早い」 |
| `unconnected` | その日のダイヤ全体でも 2 地点がつながらない | 「結ぶ路線の組み合わせがありません」 |

2026-10-09 の測定（出発 6:00〜23:00・30 分刻み）: JAIST→金沢駅は 35 時刻中 5 件（21 時以降），JAIST→小松空港は 11 件（17:45 以降．終発 17:25），いずれも緩和しても出ない終発後．0〜3 時台の出発は，従来は探す幅の外で 0 件になっていた（上の `window`）．「野町」は停留所名が「野町駅」であり，名前の不一致は従来どおり「不明な地点」になる．

### 未対応・変えないと決めた点

- 未対応: JAIST↔小松駅のシャトルの実際の経路（北側か OSRM の南側か）．公式資料・OSM に無く，既存の geojson（北側）を使っている．乗っている人への確認が必要
- 未対応: 空港バス 6 停留所の座標（既知）．徒歩の区間の線は直線のまま（道のりは `walk.json` にあるが形は持たない）．津幡〜倶利伽羅など Overpass の取得が不安定な区間は `tools/route/osm_rail_cache/` に保存して再現できる
- 変えないと決めた点: JAIST 鶴来線の geojson（OSM の路線との差が最大 72 m で，マップタブの位置の計算に影響しない）．のみバスの停留所の順（時刻表の順をそのまま使う．往復の動きは先端大学への出入りで実際の動き）
- 形は OSRM（最短・最速の車の経路）で，バスが実際に通る道と違うことがある．OSM の route=bus の路線がある系統（鶴来線）だけ実際の路線で確かめた

再作成: `python3 tools/route/build_shapes.py`（形．ネットワークが必要．取得結果は `osrm_cache/`・`osm_rail_cache/`）→ `python3 tools/route/update_geo_lines.py`（マップタブの 3 本の線）．試験は `node --test tests/shapes.test.js`（隣り合う停留所の組すべてに形がある）．
