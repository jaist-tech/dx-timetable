# のみバスの経路探索への追加と「重視する条件」選択の改修計画

## 要約

現状の検索は固定の 6 経路（`ROUTE_PRESETS`）の中だけで動くため，のみバスの追加と条件選択には，停留所グラフ全体を探索する新しい探索部（`planner.js`）が要る．計画は 5 段階（Phase 0〜4）で，Phase 0 の 3 点が決まれば着手できる．

| 項目 | 現状 | 改修で必要なこと |
|---|---|---|
| 探索の範囲 | 固定 6 経路（`multi_routes`）内の便一覧 | 全路線を 1 つのグラフにして任意の出発地・目的地を探索 |
| のみバス | 時刻表一覧のみ．README に「検索に組み込まない方針」 | 方針を変更し，12 系統（14 経路）を探索に取り込む |
| 重視する条件 | なし（出発時刻順の便一覧） | 5 条件（合計時間・金額・乗換回数・待ち時間・乗車時間）で順位付け |
| 金額 | のみバス 100 円が付箋の文言にあるだけ．他路線は無い | 路線ごとの運賃データの収集（人の作業） |

あなたの作業: 下の「Phase 0 で決めること」3 点に答える．

## 現状の確認（事実）

- 「他路線の停車駅・バス停間で経路探索できる」という記憶は，部分的にしか合わない．`public/js/search.js` の `ROUTE_PRESETS` に 6 経路があり，`utils.js` の `findConnections` は選んだ 1 経路（`multi_routes`）の区間列の中で便を組み合わせるだけである．任意の 2 地点間の探索はできない．
- のみバスのデータは `public/data/regular/nomi_*.json`（12 ファイル，14 経路）．時刻表一覧（`timetable.html`）だけが使う．`stops` は 1 本の往復列で，循環系統は始終点が同じ名前で重複し，通過しない停留所は `null` の時刻になる．
- 他路線との接続点は，連携ルート（`nomi_*_to_jaist` / `from_jaist`）の JAIST・先端大学の停留所と推察する．停留所名が既存の駅名と一致するかは未検査．
- 運賃は，のみバスの `meta.note`（100 円）以外のデータが無い（シャトル・石川線・IR・リムジン）．

## 計画

### Phase 0 で決めること（あなたの判断）

1. 運賃の扱い．「金額最低」を使うには，シャトル・石川線・IR いしかわ・小松空港連絡バスの運賃表が要る．収集する（推奨）か，金額条件を後回しにするか．
2. 探索の対象範囲．全 12 系統を一度に入れる（推奨）か，連携ルート（JAIST 発着）だけ先に入れるか．
3. 検索画面の形．今の「経路を選ぶ」画面を残し，新しい「地点指定の探索」を別タブにする（推奨）か，置き換えるか．

### Phase 1 データの正規化

- 全路線の `stops`・`schedules` から「便（trip）の停車列（停留所・時刻）」を作る関数を 1 つにまとめる（`null` は通過として除く，循環の折返しは別の便として扱う）．
- 停留所の同一視表（のみバスの「JAIST」「先端大学」と既存駅名，西金沢駅と新西金沢駅など）を `routes.json` の `transfers` に拡張する．徒歩乗換の時間も同じ表に置く．
- 路線ごとの運賃を `routes.json` に追加する（区間運賃は表引き）．

### Phase 2 探索部（`public/js/planner.js`，静的配信のままブラウザ内で動かす）

- 入力: 出発時刻か到着時刻，出発地，目的地，重視する条件．
- 方式: 乗換回数を 1 回ずつ増やして最早到着を求める方式（RAPTOR 系）で，乗換 0〜3 回の候補を集める．到着時刻指定は同じ処理を時間の逆向きで行う．
- 候補はパレート集合（合計時間・乗換回数・待ち時間・乗車時間・金額のどれかで他に負けない経路）として残し，重視する条件で並べ替える（同順なら合計時間）．
- 出力は既存の `Connection`（便一覧と詳細タイムラインが使う形）に合わせ，`status.js` と `map.js` を改修せず使えるようにする．

| 条件 | 順位付けの指標 |
|---|---|
| 合計時間の最短 | 到着時刻 − 出発時刻 |
| 金額の最低 | 運賃の合計 |
| 乗換回数の最低 | 乗車数 − 1 |
| 待ち時間の最低 | 乗換での待ちと出発前の待ちの合計 |
| 乗っている時間の最低 | 乗車中の時間の合計 |

### Phase 3 画面

- 出発地・目的地の選択（のみバスの停留所を含む検索付き一覧），出発／到着の切替，重視する条件の選択（5 択），日付（既存の 7 日先まで）．
- 結果は現在の便一覧と同じ見た目で，条件ごとの指標（所要・運賃・乗換・待ち・乗車）を各行に表示する．
- `i18n.js` に日英の文言を追加する．

### Phase 4 検証

- 既存 6 経路で新しい探索と `findConnections` の結果を突き合わせる（同じ出発地・目的地で便が一致するか）．
- のみバスは時刻表 PDF の数便と手で照合する．日種別（平日・休日・特別ダイヤ）と日付またぎ（終電後）の境界を試す．
- Codex のレビューを commit 前に回す．

### 規模と主な危険

| 項目 | 内容 |
|---|---|
| 規模の見込み | Phase 1〜2 が中心．探索部は新規約 400〜600 行と推察する |
| 危険 1 | のみバスの停留所名の表記ゆれで，接続が欠ける（Phase 1 の同一視表と検査で防ぐ） |
| 危険 2 | ブラウザ内の計算量．全便で数千〜数万の停車なので，通常は問題にならないと推察する（Phase 2 で計測する） |
| 危険 3 | 運賃の取得元が PDF・公式サイトに分かれる（Phase 0 の判断 1） |
